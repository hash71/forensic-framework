# WARRANTLAB Reproduction

## Environment

Use Python 3.11 and install the frozen research environment:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-research.lock
```

Tectonic is the only non-Python dependency needed to compile the manuscript.
The paper figures use the Bitstream Vera fonts shipped with ReportLab, so the
artifact generator does not depend on host-specific fonts.

## One-command analysis and paper rebuild

From `forensic-framework/`, run:

```bash
.venv/bin/python reproduce_warrant_paper.py \
  data/warrant_runs/<complete-synthetic-run> \
  --external-run-dir data/warrant_runs/<complete-external-run>
```

The command rejects incomplete or duplicate runs, verifies each benchmark
checksum against its manifest, regenerates `analysis.json` and
`statistics.json`, runs the full test suite, regenerates all LaTeX macros and
vector figures, and compiles `conference_paper/build/paper.pdf`. When supplied,
the adjudicated human analysis must be checksum-bound to the same synthetic
records file or the rebuild stops.

For a reviewer artifact that deliberately omits every raw model transcript,
add `--allow-omitted-raw`. This mode is all-or-none: a partial raw-response set
or any retained-file hash mismatch still fails. After real adjudication exists,
also add
`--human-analysis data/warrant_annotations/<package>/human_analysis.json`.

Use `--no-compile` when Tectonic is unavailable. Use `--skip-tests` only after
the unchanged environment has already passed the same commit's tests.

## Full model reproduction

The analysis command does not contact a model provider. To reproduce model
inference, configure the endpoint variables documented in `.env.example`, then
run `run_warrant_llm.py` with the conditions, variants, repetitions,
temperature, maximum tokens, and model identifiers stored in the frozen run
manifest. Raw responses and record lines are append-only. Use a new `run_id`;
do not write into the released run directory.

The current remote endpoint exposes only an alias and no model revision. A
fresh provider run can test procedural reproducibility, but it cannot be
claimed as bitwise reproduction of that revision-opaque deployment.

## Human validation

`prepare_warrant_annotations.py` creates the deterministic blind package and
authenticates the exact synthetic or external case corpus from the run
manifest. Only its `blind/` directory may be shared with independent
annotators; the administrative key reveals condition, family, mutation, and
expected verdict. After both reviews freeze,
`prepare_warrant_adjudication.py` creates a second blind interface containing
the two reviewer labels and rationales but no system metadata or identities.
`analyze_warrant_annotations.py` rejects incomplete or non-independent files
and calculates overall and per-axis agreement, Cohen's kappa,
sampling-design-weighted estimates, and mechanical-checker performance against
the adjudicated labels. It adds deterministic, within-stratum bootstrap
intervals for the principal agreement and mechanical-validation endpoints. It
also joins sampled claims to the frozen shared-response records and produces
the human-labeled primary safety contrast with a two-stage claim-stratum and
base-case bootstrap. That estimate replaces the mechanical proxy in the
paper's abstract and conclusion whenever a checksum-bound human analysis is
supplied.
Expert labels and adjudication are empirical inputs and
cannot be regenerated by code.

## Anonymous artifact

After the final paper and all release-run directories have passed redaction,
build a deterministic anonymous archive from a clean commit:

```bash
.venv/bin/python build_anonymous_artifact.py \
  --development-run-dir data/warrant_runs/development-remote-fusion-gemma-v1_4 \
  --synthetic-run-dir data/warrant_runs/<confirmatory-run> \
  --external-run-dir data/warrant_runs/<external-run> \
  --human-package-dir data/warrant_annotations/<final-package> \
  --human-analysis data/warrant_annotations/<final-package>/human_analysis.json \
  --paper-pdf ../conference_paper/build/paper.pdf
```

Omit `--human-analysis` until a complete, independently adjudicated,
checksum-bound analysis actually exists. The artifact README and manifest
distinguish an unfilled annotation package from completed expert validation.

The builder uses an explicit allowlist, excludes private record backups and
environment files, validates run cardinality and release hashes, scans for
workstation paths, configured author identity, and credential-like values, and
writes a deterministic ZIP plus a per-file SHA-256 manifest. Raw model
transcripts are included by default for output-level auditing. Pass
`--omit-raw` when provider or endpoint-operator redistribution terms have not
been archived and reviewed, or when the conference artifact-size limit
requires it. Scored structured records and response hashes remain available in
the reduced package.

Full confirmatory `records.jsonl` files and per-call `raw/` directories are
intentionally excluded from ordinary Git history because they are large,
generated artifacts. Git tracks the exact run manifest, release-redaction
report, aggregate analysis, statistics, code, and paper; the deterministic
reviewer/public artifact carries the sanitized bulk files and binds every file
with SHA-256. This preserves auditability without permanently inflating the
monorepo.
